# Optional video-quality stack — capability, license, cost, and integration audit

**Reviewed:** 2026-09-30. This is a public-source/README/license-path review, not legal advice, a code/security audit, an install test, a model benchmark, or a rights clearance. No candidate repository was cloned, installed, executed, or copied; no model weights were downloaded; no paid/API/GPU calls were made. Model cards, checkpoints, repository branches, and terms can change.

## Decision in brief

Do **not** replace CreatorOps' current renderer or install the whole proposal. Treat each feature as an optional adapter and approve/test one capability at a time.

- **Best later renderer POC if a new engine is needed:** [HyperFrames](https://github.com/heygen-com/hyperframes), for deterministic HTML-to-video compositions, branded overlays, and animated captions. It is a renderer/framework, not a video-generation model or a complete autonomous editor. Its README requires Node.js 22+ and FFmpeg. This workspace currently reports Node `v20.20.2`, no `ffmpeg` executable on `PATH`, and no usable `nvidia-smi` probe, so no local render/model benchmark was possible. Preserve the existing render fallback.
- **Caption design:** use the MIT-licensed [motion-skills](https://github.com/iart-ai/motion-skills) ideas as optional design guidance. Its separate [kinetic-typography-skills](https://github.com/iart-ai/kinetic-typography-skills) pack overlaps a skill in the hub; do not install both. Keep transcript correction and the existing manual Hinglish SRT path. Do not merge the separate [AI Video Captions](https://github.com/nicolaigaina/ai-video-captions) web app just to get caption styles.
- **Hindi voice candidate:** [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) is worth a small, approved local POC: its official inference README documents Hindi (`lang_code='h'`), and the official model card/repository identify Apache-2.0 weights/code. This is not a promise of natural Hinglish/code-switching, a voice-quality score, or zero setup cost; test actual Hindi names, accents, pronunciation, pacing, and dependencies before switching from a configured provider. [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) does not list Hindi among its official supported languages; its cited 97 ms is first-packet streaming latency, not full narration render time.
- **Defer video generation and upscaling:** none is needed for the baseline GTA VI clip path, which should use authorized gameplay and must not make synthetic footage look like real in-game events. LTX-2.5, Wan 2.2, HunyuanVideo, and the newly logged LTX-2.3 GGUF/Kaggle or LTX Desktop route have different output limits, licenses, and hardware requirements. The exact 14.3 GB Q4_K_M file, full ComfyUI dependencies, Kaggle GPU/disk availability, and target-hardware speed are unverified; LTX Desktop's current local Windows/Linux minimum is 16 GB VRAM, not 12 GB. HappyHorse is not integration-ready on the evidence checked. Do not download weights, allocate a cloud/Kaggle GPU, or call a paid service without separate explicit approval.
- **Keep music generation optional:** ACE-Step 1.5 is a plausible local experiment only after checking the exact checkpoint's terms, resource needs, and generated-track rights. Its upstream commercial-use and speed statements are publisher claims, not independent clearance or benchmarks.
- **Keep QA and public posting separate:** automated checks may find technical problems, but cannot approve rights, factuality, or final quality. Preserve a human full-playback review and explicit approval before public posting. Do not use a `4/5` score as a publish gate.

## CreatorOps implementation update — 2026-09-30

One low-risk caption feature has now been added directly to CreatorOps; this did **not** integrate or copy a candidate repository. The GTA VI clip form has an optional `kinetic_karaoke` mode: it generates an ASS word-highlight subtitle from the manually entered caption lines, asks FFmpeg's ASS/libass filter to burn it into the MP4, and retains the SRT sidecar. Standard SRT remains the default. Word timings are evenly estimated from each caption line, not transcribed or aligned, and must be proofread/resynced.

Python compilation, browser JavaScript syntax checking, and all 16 unit tests passed; tests used a temporary SQLite database. **End-to-end MP4 rendering and visual review remain unverified** because this workspace has no usable FFmpeg executable (including the `imageio-ffmpeg` fallback). No repositories or model weights were installed/downloaded, no GPU/cloud/API/paid calls were made, and the original rights/human approval/publishing gates are unchanged.

## Proposal-claim and spec check

| Proposal claim/spec | Review finding | Safe product wording |
|---|---|---|
| “Native 4K” / 4K60 final video | A model's advertised maximum or an upscaler's output dimensions do not prove native 4K detail, clean motion, or 60 fps. The project must separately verify actual width/height, aspect ratio, frame rate, frame pacing, and visual quality. | Say “rendered/upscaled to the selected dimensions” only when measured. Never call 720p-to-4K restoration native 4K. |
| `1080x1920, 60fps, 4K` | These dimensions are vertical 1080p, not vertical 4K. A common 9:16 4K target is `2160x3840`. “4K” without the actual dimensions/aspect ratio is ambiguous. | Store the requested profile explicitly; report actual probed output properties. |
| 720p/1080p upscaling with Real-ESRGAN | Frame-by-frame enhancement can add apparent sharpness but can also cause temporal flicker, warped detail, or inconsistent textures. It cannot recover true source detail. | Require a motion/flicker test and human playback review. Keep the source-resolution render available. |
| “60-second short from about 40 words” | At ordinary narration pacing, 40 words is usually substantially shorter than one minute. Runtime depends on pauses, delivery, and editing; time the actual narration rather than infer duration from word count. | Make script length and final duration separate measured fields. |
| “15–25 minutes end-to-end” | Not benchmarked. The estimate omits or may not include cold model downloads, clip count, retries, GPU contention, caption correction, upscale, encoding, upload, and human review. A 5-second sample is not a one-minute finished-video benchmark. | Publish only a measured range tied to exact hardware/model/version, clip length/count, resolution, warm/cold state, and provider. Otherwise show “not measured.” |
| LTX “0.85 seconds”; Qwen “97 ms” | Neither number establishes complete video/narration generation time. Qwen's cited figure is first-packet streaming latency. LTX runtime is model, resolution, frame count, precision, and hardware dependent. | Do not display either as per-video completion time. |
| “₹0” / “free GPU” | Open weights/code do not eliminate electricity, hardware, storage, maintenance, data transfer, API fees, or changing hosted free-tier quotas. Kaggle/Colab-style sessions are not an always-on production guarantee. | Show known costs/quotas and unknowns; ask before any paid/hosted run. |
| “10-year editor,” “4/5 QA,” “4/5 agents” | These are marketing metaphors or unvalidated heuristics, not measured editor experience, a quality standard, or a prediction of audience success. | Keep scores advisory and explainable; never let them clear rights or publish. |
| `-14 LUFS` plus `-18 dB` music ducking | Useful as an optional starting mix profile, not universal loudness/clarity rules. Program loudness and true peak should be measured; music must be auditioned beneath speech. | Make targets configurable, record measured values, and require human audio review. |

#### LTX-2.3 ComfyUI/Kaggle setup and LTX Desktop alternative — candidate only, not executed

- **Model artifact and license:** the exact proposed `dev/ltx-2-3-22b-dev-Q4_K_M.gguf` exists in the third-party `vantagewithai/LTX-2.3-GGUF` repository and its Hugging Face file page reports 14.3 GB. The repo card declares `license: other` / `ltx-2-community-license-agreement` and links to Lightricks' terms. The official LTX-2.3 model card links `LICENSE-2`; this is not an Apache-licensed model-weight release. Check the precise version, third-party quantization provenance/redistribution, and commercial/output terms before use. The selected file is the `dev` variant; the official card describes a separate distilled 8-step checkpoint, so do not infer speed from the file name or an unrelated demo.
- **ComfyUI is more than one GGUF download:** LTX-2.3 supports joint video/audio generation at the model-family level, but that does not validate this specific GGUF workflow. The model card recommends ComfyUI's LTXVideo nodes; the third-party repo also carries a workflow JSON. Before any run, verify the workflow revision, ComfyUI-GGUF node and versions, text encoder, video/audio VAE or other required components, and optional spatial/temporal upscaler weights. A single GGUF file is not a complete install. Confirm actual output dimensions/frame count and preview every audio/video result.
- **Quality/runtime claims:** the reviewed official card labels the model language as English and warns that audio without speech may be lower quality. Robust Hindi/Hinglish speech, a 720p 10-second render, a 16 GB T4 fit, generation time, and upscaler benefit are all **unverified**. Joint audio/video generation is not a guarantee of natural narration or licensed music. Real-ESRGAN remains an optional, separately tested post-process; compare for flicker and artifacts and retain the original.
- **Kaggle constraints:** do not assume an eligible free single 16 GB T4, free quota, or persistent disk. Kaggle's published accelerator/session/storage limits are account- and availability-dependent; check the actual notebook account/session before planning a run. The 14.3 GB GGUF alone leaves limited room on a small session disk, before auxiliary weights, caches, software, and outputs. Do not launch a notebook or upload project files/secrets without separate explicit approval.
- **LTX Desktop:** the official README identifies the app as beta, says LTX-2.5 Fast is the local default and LTX-2.3 Fast remains selectable, and says local Windows/Linux requires at least 16 GB VRAM (not 12 GB), 16 GB system RAM (32 GB recommended), and 160 GB+ free disk on Windows. macOS Apple Silicon local mode requires at least 15 GB free RAM. Unsupported local hardware can route to API-only mode requiring an LTX API key; this project must keep that route disabled absent explicit provider/privacy/cost approval. GitHub API metadata reports Apache-2.0 for Desktop code, but does not change the model-weight license or third-party dependency terms.
- **If later approved:** choose one route (target-machine ComfyUI or Desktop; use Kaggle only if its real accelerator/quota/storage are confirmed). First generate a short, neutral, non-GTA test, record the exact model/workflow/nodes, actual GPU/VRAM, disk, duration, dimensions, FPS, audio presence, and wall time, then have a human review sync/artifacts. No GTA VI scene, publishing, or claim of successful generation is authorized by this plan entry.

## Safe phased integration for Antigravity

1. **Audit only:** inspect the existing CreatorOps renderer, clip pipeline, caption format, optional voice providers, tests, license notes, and deployment/runtime. Report what actually works and what is missing. Do not clone/install any candidate, download weights, request a cloud GPU, or call an API.
2. **Caption/render validation:** the optional custom `kinetic_karaoke` ASS/libass mode is implemented in CreatorOps. After approval and once a supported FFmpeg build is available, test it on synthetic or operator-owned media; compare it with the default SRT sidecar, inspect Hindi/Hinglish glyphs, timing, line breaks, contrast, and safe areas, then report measured render metadata. Evaluate HyperFrames only later if CreatorOps needs a different renderer; do not add a second editor by default.
3. **Optional speech recognition / voice (separate approval):** test one ASR/alignment backend, not WhisperX plus Stable-ts plus a separate captions app. Test Hindi names and code-switching; keep edits visible and human-correctable. For TTS, test Kokoro Hindi first on an approved local script; do not promise Hinglish until a human review passes. Do not send scripts/audio to a hosted service without explicit provider/privacy approval.
4. **Optional music (separate approval):** verify the exact ACE-Step checkpoint/model terms, compute/storage, data handling, commercial/output terms, and platform policy. Generate a short test only; compare against licensed non-AI music and require an audition. Keep music disabled by default.
5. **Optional video generation/upscaling (separate approval):** start with one short, non-GTA synthetic/original B-roll test only after confirming GPU, disk, precise model weights/license, and a cost/time budget. The LTX-2.3 Q4_K_M GGUF/Kaggle-ComfyUI route and LTX Desktop are now documented as optional candidates, not working integrations: validate all auxiliary models/nodes and the exact workflow; do not assume a free Kaggle T4/quota or 720p/10-second runtime. Desktop local Windows/Linux requires at least 16 GB VRAM under the checked README; disable API fallback absent explicit approval. Never auto-download 20–70GB models or consume cloud quotas. For GTA VI, use rights-cleared actual footage and never present generated scenes as in-game captures.
6. **QA and publishing:** add machine-readable metadata checks (dimensions/aspect/FPS/duration/audio track and measured loudness where tools exist) plus complete human playback review. Test subtitle sync, crop/safe areas, visual flicker, narration intelligibility, music rights, black frames/cuts, and loudness. A passing script/test or score never substitutes for human review, source-rights clearance, or owner approval. Keep YouTube-first/private-by-default; require the existing human approval before any public upload. Do not enable five-platform posting as part of a renderer change.

## Standing CreatorOps constraints

- Keep `ch-1` U.S./`en-US` and the separate `ch-2` India/`hi-IN` GTA VI draft workflow unchanged. Preserve existing read-only viewer, secrets handling, policy checks, data, and tests.
- GTA VI footage must be operator-supplied and rights-controlled. A recording owner's permission does not clear game IP/music; preserve the existing written commercial-permission, original-commentary, no-leaks, human render-review, and publish gates. AI-generated footage must not be described or shown as actual game footage.
- YouTube remains the first/only uploader unless each other platform receives a separate official-API, account-consent, app-review, quota, and cost audit. Do not bypass access controls.
- Preserve the manual caption, current renderer fallback, and configured voice provider until an approved alternative is tested. Mark unavailable/unconfigured/untested honestly.
- No guarantee of 4K detail, 60 fps, editor-level quality, 15–25-minute turnaround, Hindi/Hinglish accuracy, zero cost, monetization, or audience growth.
