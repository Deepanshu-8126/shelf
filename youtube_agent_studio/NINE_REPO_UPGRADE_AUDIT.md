# Nine-repository upgrade proposal — capability, license, and risk audit

**Reviewed:** 2026-09-30. This is a light review of public GitHub pages, README claims, and checked `LICENSE`/`NOTICE` paths—not a legal opinion, security audit, code review, install test, benchmark, or end-to-end validation. No repository was cloned, installed, executed, or copied into CreatorOps. Repository branches and terms can change.

## Bottom line

**Do not combine all nine repositories into CreatorOps.** They overlap heavily, use incompatible stacks, and do not jointly deliver the advertised guarantees of `₹0`, ten-agent quality, reliable `4/5` consensus, five-platform autopublishing, automatic niche switching, and zero human input. Several repositories have no checked license; some rely on API keys, hosted services, GPU/CPU resources, browser sessions, or URL-download behavior. The safer route is to keep CreatorOps as the base and implement only small, tested, rights-gated capabilities after an explicit review.

## Claims check

- **“₹0”:** not a reliable end-to-end claim. Self-hosting avoids some subscription fees but still requires a computer, storage, electricity, maintenance, and sometimes paid/quota-limited inference, voice, storage, or social-posting APIs. Free tiers can be capped or changed.
- **“4/5 agreement guarantees a winning clip”:** no. The checked Viral Clip Agent README describes a ranking formula, not a validated predictor. Multiple prompt personas are not necessarily independent evidence, and no score guarantees audience response.
- **“Ten agents means better production”:** not established. It is an architecture claim, not a measured quality result; more calls can add cost, latency, and correlated mistakes.
- **“GTA VI search +400%” or a 24-hour niche flip:** no methodology or independent evidence was supplied. A percentage needs a named source, baseline, time window, sample, and formula. A 24-hour result is not enough to rewrite a channel strategy automatically.
- **“Autopublish to five platforms”:** no one of these repositories establishes a free, approved, fully working YouTube + Instagram + TikTok + Telegram + Discord pipeline. YouTube uploads need OAuth; Instagram publishing requires an eligible professional account and app permissions; TikTok direct posting requires an approved scope and user authorization, and unaudited clients are restricted to private posts. Telegram/Discord need separate bot/webhook handling.
- **“NO HUMAN INPUT”:** safe only for low-risk read-only research and draft generation. Rights clearance, account consent, final media review, and public publishing remain human-controlled gates—especially for GTA VI.

## Recommended CreatorOps design

1. **Keep the current app and channel separation.** Preserve `ch-1` as U.S./`en-US`; keep the GTA VI India/`hi-IN` workflow separate in `ch-2`. Do not let one channel’s metrics silently retarget another.
2. **Keep three clipping layers advisory:** (a) a fail-closed source/rights check; (b) local timeline cues such as the current frame-change suggestions plus optional local speech/audio cues; (c) explainable candidate scoring. A multi-agent score may rank clips for review, but must not clear rights or publish a clip.
3. **Build a read-only daily research loop:** use permitted public metadata sources and show source, collection time, sample size, baseline, and limitations. Use authenticated analytics only for channels the owner controls. Never present competitor retention/revenue as visible data.
4. **Treat niche changes as recommendations.** Use enough evidence over a configurable multi-week window and require owner confirmation to change a channel’s niche, region, or language. Do not auto-switch on a 24-hour spike.
5. **Stay YouTube-first.** Keep the existing official YouTube OAuth path and private-by-default settings. Add other platform adapters only after reviewing official API requirements, account consent, app approval, scopes, quotas, and cost. No browser automation or third-party autoposter should silently bypass those gates.
6. **Keep GTA VI source/release gates.** Local access to footage does not establish game-IP permission. Rockstar’s fan-video policy describes general fan use as non-commercial, prohibits leaked pre-release footage, and says commercial licensing requests are considered case by case. Streamer permission/credit is not permission to commercially exploit Rockstar IP. Require appropriate written permission and meaningful original commentary before any monetization-oriented public post.

## CreatorOps baseline and validation boundary

The current project already has a separate GTA VI clipping workflow for local operator-supplied footage, manual Hinglish captions, optional configured Hindi voiceover, and rights/review gates. Its OpenCV suggestions detect visual change only, not semantic gameplay events. At the last recorded validation, all 12 existing tests and Python/JavaScript syntax checks passed; API smoke checks returned HTTP 200. FFmpeg was unavailable, so an actual MP4 render and a real publish request were not verified. This proposal did **not** change application code or test any of the nine repositories. The later optional 4K/captions/editing/audio/QA proposal is assessed separately in [`VIDEO_QUALITY_STACK_AUDIT.md`](VIDEO_QUALITY_STACK_AUDIT.md); it does not replace these rights, cost, or human-approval gates. The staged Antigravity prompt covers both proposals.
